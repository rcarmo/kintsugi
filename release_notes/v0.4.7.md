# Kintsugi v0.4.7

## Workspace exec with delegated cgroups

Fixes `docker exec failed` / `error starting setns process: exec: already started` in systemd-based workspaces after the Go 1.26 runtime rebuild.

Systemd moves its init process into a child cgroup and enables controllers in the parent. Linux then rejects runc's `CLONE_INTO_CGROUP` launch into that parent with `EBUSY`. runc 1.4.0 tried its fallback using the same `exec.Cmd`; Go 1.26 forbids calling `Start` twice, even after a failed launch. This prevented otherwise healthy workspaces from starting their helpers or accepting terminal commands.

The pinned Ubuntu runc source and distribution patches are retained, with the complete upstream [runc #5091](https://github.com/opencontainers/runc/pull/5091) source fix backported: check command-construction errors and use a fresh command for the fallback. The runtime reports `1.4.0-0ubuntu1+kintsugi-exec-retry` and retains Go **1.26.10**, seccomp and the existing resource/network boundaries. No cgroup controllers are disabled and no policy limits or stored formats change.

## Update scope

A paired installation update is needed: the System image provides the runtime that executes workspace processes. Updating only the app does not fix this failure. Existing workspace containers, data, configuration and saved parked intent are retained; the installation update interrupts running workspaces.

Publication advances `latest` and does not move `stable` or update an installation automatically. The local installation is upgraded separately through the supported updater after verified publication. No fresh physical-host reboot or sustained stress acceptance is implied.
