# Kintsugi v0.7.0

## SQLite Agent history

- Store built-in Agent state, timeline, search indexes and retained tool/MCP copies in one `agent.sqlite`, using Bun’s built-in SQLite with WAL and full synchronous writes.
- Stream existing JSONL journals into a verified SQLite store on first open, then keep the original files in `jsonl-backup`. Imports run in a Bun worker so writer-lease heartbeats stay responsive. Large histories can take several minutes to convert.
- Read retained history through read-only connections without resuming tasks. Bound history pages by entry count and UTF-8 bytes, and keep tree projections separate from full payloads.
- Add `grep_history` with bounded RE2 matching, filters, surrounding context and continuation cursors. Share the SQLite index with `search_history`, including late commits with earlier reserved entry IDs.
- Deduplicate media by content hash. Keep upload references small in conversation entries and fetch original bytes separately for authorised downloads.

## History and retained outputs

- Restore built-in `/tree` from both Enter and Send, with bounded navigation, labels and safer focus handling. External CLI commands keep their existing behaviour.
- Preserve visible transcript scrollback across context compaction.
- Migrate existing MCP recall IDs and pins while preserving as-of branch visibility and current grant/retention checks. A later fork cannot restore a forgotten or expired cached copy from old journal documents.
- Fix output expiry after clock rollback, IDs evicted during their own save, background-pruning shutdown and abandoned temporary snapshots. Retain exact UTF-16 output, including a truncation boundary through a surrogate pair, while keeping text search available.
- Publish recall schema and full-text index upgrades atomically. Describe incomplete stored copies accurately and leave raw tool results unchanged inside code-mode scripts.

Local verification passed 3,927 backend tests and 64 native tests, plus lint, types, locked dependency installation and production assets. Manual history review and eight no-inference composer scenarios passed. Real-device Safari/keyboard and real-model quality/cost acceptance remain separate checks.

## Compatibility and channels

System compatibility remains 7, the app minimum remains 0, and network/resource policy readers remain 2 and 3. Custom release sources and image pins remain authoritative.

Publication advances `latest` and leaves `stable` at v0.6.12. It does not deploy, migrate or restart an installation; journal conversion occurs when the new app first opens that history.
