# Kintsugi v0.6.7

## Learning and review

- Review proposed facts in the transcript, with full claims, evidence, optional notes and **Approve**, **Wrong** and **Stale** controls. Learning entries containing proposals open automatically.
- Apply eligible observations and approved advice on the next request in an ongoing session. Learning checks completed tool results between replies; model proposals have separate evidence and cooldown limits.
- Require exact-text approval for inferred advice, honour shared fact and estimated-token budgets, and preserve feedback through journal compaction and reopening. A learning result that finishes late cannot restore rejected advice.
- Use authoritative tool outcomes and describe earlier observed failures without inferring permanent network or environment restrictions.
- Correct Settings labels for request limits and evidence checks. Preserve Watch-only behaviour, explicit fact removal, and fork/rewind snapshots.
- Incorporate upstream fixes for Git global options, wrapped verification commands and Ruby test commands, with source attribution retained.

## MCP connections and recall

- Exclude sensitive tools and detected secrets from recall, including access to previously retained matches. Off blocks capture and access without erasing unexpired copies.
- Refresh duplicate-result metadata and enforce exact tool filters and exclusive forget selectors. Clarify capture-based retention, storage caps and the separate source journal.
- Connect to resource-only servers without requesting unsupported tool discovery. Refresh advertised tool-list changes on the existing connection without replaying effectful calls.
- Include the background tool discovery and transient connection recovery committed since v0.6.6.

## Workspace interface

- Add sidebar CPU, memory and I/O meters for the selected workspace and System, sampled on a shared timer while subscribed.
- Recover stale live connections, including WebSocket and SSE reconnection handling.
- Preserve tablet composer focus when resizing and improve the resize grip.

## Compatibility and verification

The optimizer remains experimental and off by default. Recall and learning changes are app-owned. Resource meters use optional System capability 6; the app minimum remains 0. Network and resource policy readers remain 2 and 3. Existing release sources, pins and rollback behaviour are unchanged.

Local verification passed 910 tests across 38 sequential files, with 3 existing skips in the Host terminal lifecycle fixture and no failures. One-thread lint, TypeScript for the complete optimizer package, production web assets and diff checks passed within fixed memory/process limits.

Full-repository checks and native AMD64/ARM64 image verification are required before publication; the full local TypeScript check was not repeated after reaching its memory limit. Browser review used synthetic Chromium fixtures; physical iPad/iOS/WebKit and installed-production acceptance have not been verified.

Publication advances `latest`, leaves `stable` unchanged and does not update or restart an installation.
