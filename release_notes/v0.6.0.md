# Kintsugi v0.6.0

## Token optimizer

- Add an opt-in token optimizer for built-in Agents and their subagents, ported from Microsoft [TokenEconomizer](https://github.com/microsoft/TokenEconomizer) (Apache-2.0). It is off by default and experimental.
- **Settings → Token optimizer** offers Off, Watch only and On, with Basic, Model-assisted and Custom presets. Basic remembers facts about each repository, nudges runs that keep repeating the same failures, and suggests hiding tools that never get used, without extra model calls. Model-assisted adds model-written facts, a stuck-run judge, nudge writing and task-aware tool picks, within per-session and daily call limits. Advanced settings cover limits, per-task models, call savers and local classifiers.
- Each Agent's row shows the facts it uses and has learned, suggested and hidden tools with the reason, and recent nudges with their text. Actions include hiding suggested tools, sticky Restore, removing learned facts from one Agent, and per-workspace or per-Agent overrides, including for workspaces that aren't running.
- Subagents see their root Agent's facts and get their own nudges and nudge budget. Tools used by subagents and one-shot Agents count as used, so they are never suggested or hidden.
- Optional automatic tool picks run before a new prompt while the Agent is idle, including attachment types. A slow or failed pick never holds a prompt for more than 20 seconds.
- While the optimizer is on, the Agent composer footer shows a status chip (mode, facts, hidden tools, and a dot for waiting suggestions or a nudge this run). Clicking it opens that Agent's row in Settings. It is the first footer item to drop on narrow screens, and footer status text is one step smaller.
- A "still looks stuck" transcript note offers Stop while its run is still going.
- The built-in Agent prompt states that code mode is a native tool, not a CLI to install.

## Browser connection

- Add a per-browser choice of WebSocket or SSE live updates in Settings, for browsers that can't hold a WebSocket (for example iOS with a self-signed certificate). The section stays usable while live updates are paused.
- Browser tabs show the workspace and selected Agent, such as `workspace - @agent`.
- File-browser listing requests are no longer routed through preview isolation.

## Compatibility

App-only. System compatibility stays at 5, the app minimum at 0, the network-policy reader at 2 and the resource-policy reader at 3. The token optimizer adds journal documents, background tasks and a private settings file in app data; it is inert until enabled. An older app opens journals written with it (tested), leaving its background tasks waiting. **Before downgrading, restore any hidden tools** in Settings → Token optimizer: older versions keep them hidden and have no Restore button. Settings sections can now reveal one item through `?focus=`.

## Verification

`bun run check` (workspace-module generation, lint, TypeScript) and `git diff --check` passed. The full local main suite passed 3,555 tests with 36 skips and no failures across 420 batches. The production client asset build also passed. The token optimizer's offline acceptance covers memory, SQLite and JSONL storage, reopen, fork, rewind, compaction, reset, subagents, the real prompt-submission path, provider request serialization with networking blocked, and downgrade. A pinned upstream differential harness regenerates 724 cases byte-identically, and focused upstream TokenEconomizer tests passed (420, 2 skipped).

A targeted browser check rendered the composer footer with real CSS and its layout controller at 900, 600 and 390 pixels. The full composer-layout acceptance and the browser-transport recovery acceptance were not re-run for this release.

## Known limitations

The token optimizer has not been checked against real model providers or a running installation, and Model-assisted cost and quality are unmeasured. Local classifiers stay inactive until they have enough reviewed examples. Learned facts stay within one workspace, and daily call limits are per workspace. If the app restarts mid-run, a subagent's loop guard resumes from its saved state without re-checking earlier tool results.
