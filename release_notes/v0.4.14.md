# Kintsugi v0.4.14

Adds explicit acceptance of self-signed or untrusted HTTPS certificates when connecting a Gitea server, with setup and persistent connection warnings.

## Gitea certificate option

- Certificate verification stays enabled by default. Select **Allow self-signed or untrusted HTTPS certificates** only for a server you trust. This disables verification for the configured HTTPS host and port; it does not pin or authenticate a self-signed certificate. An attacker able to impersonate that endpoint could steal the token.
- The exception is derived from the entered server URL, with no hardcoded exception hosts. Wildcard hostnames are rejected. Existing saved connections without the option remain strict.
- Token validation, repository search, host-side Git operations and workspace proxy upstreams honour the same configured origin. Explicitly configured non-default HTTPS CONNECT ports retain their authority through the proxy.
- Other origins keep strict TLS. Private-network permissions, token-host/origin restrictions, DNS pinning, response scrubbing and SSH trust are unchanged. Git disables redirects for the exception's URL scope; API requests also refuse redirects.
- Reconnecting without the option or disconnecting removes the exception from newly acquired connection/proxy contexts. No global TLS environment override or new application environment variable is introduced.

## Verification and update scope

Local verification passed **2,716 tests**, with **36 skipped** and **zero failures**, plus frozen install, lint and TypeScript checks. A real self-signed HTTPS fixture verified API access, repository search and authenticated Git access after opt-in, rejection before opt-in and after revocation, strict TLS on other hosts/ports, and redirect refusal. Proxy regressions verified exact-origin scope, destination pinning and configured HTTPS CONNECT ports.

Manual app checks confirmed that the checkbox starts unchecked, strict validation rejects the fixture certificate, explicit acceptance connects successfully, and the warning persists after reload. The fixture used isolated preview data; no real user credentials or Gitea instance were changed. No UI assertions were added to the test suite. Tagged publication separately requires full CI and native packaged System/app boot checks.

No dependency, runtime-image pin or installation compatibility-counter changes. The saved certificate option is optional; no data migration is required. Fork safeguards and attribution remain unchanged. Pre-existing local resource-default edits are excluded.

Publication advances `latest` only. `stable` remains v0.4.10. No existing installation is updated or restarted.
