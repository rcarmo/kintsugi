# Kintsugi v0.8.0

New workspaces start with an **8 GiB disk limit** when the App and System are both updated. The checkout, private home files and nested Docker storage share that limit. Existing workspaces keep their current storage. Shared files and base images don’t count towards it.

Open **Workspace Properties → Disk** to see usage and free space, or increase the limit without restarting. Disks can grow but can’t shrink. If growth is interrupted, Properties shows the size that was actually applied and lets you retry.

Clipped action menus now show a small chevron when more actions are out of view. **Changes** opens immediately while Git loads the diff and offers **Try again** if loading fails.

## Before updating

Update the whole installation to enable disk limits. Updating the App alone on an older System leaves new workspaces on the previous storage layout.

Once a managed disk exists, the installer blocks rollback to versions that can’t read it. Take a consistent backup before updating if you need to return to an older version. The [v0.7.7 journal rollback warning](v0.7.7.md#before-upgrading) still applies if you’re upgrading from v0.7.6 or earlier.
