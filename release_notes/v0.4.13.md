# Kintsugi v0.4.13

Fixes false workspace OOM shutdowns, restores reusable conversation prefixes around live plans, and adds token-weighted family CH.

## Workspace availability

The System resource monitor used hierarchical `memory.events` counters, so an OOM confined to a child cgroup could park and stop an otherwise healthy workspace. It now reads the workspace boundary's local `oom_group_kill` counter. Workspace-level group-OOM and Docker OOM-exit containment remain enforced; memory limits and explicit retry/cooldown safeguards are unchanged.

Helper transport failures now distinguish available stopped, running and OOM status instead of suggesting an old image needs recreating. Status inspection has a cancellable two-second bound. It never restarts a container or replays an unsafe RPC.

The original diagnostic exhausted memory in a standalone inspection script that retained quadratic copies of request prefixes. That script was corrected separately. Runtime regressions use fixture counters; no further live OOM was triggered to verify this release.

## Prompt reuse and plans

The live plan is request-only context. Its final Anthropic-style cache boundary could disappear from the next request, preventing reuse of the conversation history. The plan hook now moves the existing marker before that transient suffix. Real Pi provider-serializer tests confirm the canonical prefix survives into the next request, including string and block content. No extra marker, longer TTL or warming inference is introduced; disabled caching stays disabled.

Plan mutations return compact plain-text acknowledgements. Explicit reads return Markdown. Historical full-plan JSON is shortened in model context only; persisted journals, raw details, ownership and revision checks remain intact. The latest plan snapshot remains transient, outside journal history. Upgrading can require a one-off prefix warm-up; provider-side CH and billing savings have not been measured.

## Own and family CH

`CH 80% / 75%` shows this branch first, followed by this branch plus its delegated, one-shot and nested descendants when present. Family CH divides summed read hits by summed prompt tokens; it does not average percentages. Descendant branches are counted once, independent roots are excluded, and model-attribution mirrors are not counted as additional usage. Cost retains its own-plus-descendant breakdown.

## Verification and update scope

Local verification passed **2,711 tests**, with **36 skipped** and **zero failures**, plus frozen install, lint, TypeScript and System bundle checks. Manual app fixtures verified own/family CH and compact plan results without external inference. Composer layout passed **89/89 checks across six no-inference Chrome scenarios**; live provider sends, busy/long-transcript states and physical/iOS keyboards are not qualified. Tagged publication separately requires full CI and native packaged System/app boot checks.

Use a paired installation update to activate the System OOM-monitor fix. An app-only update supplies the plan, CH and helper-diagnostic changes but leaves the installed System monitor unchanged. Publishing performs neither update.

No dependency, runtime-image pin, compatibility-counter or persisted-format changes. Fork safeguards and attribution remain unchanged. Pre-existing local resource-default edits are excluded.

Publication advances `latest` only. `stable` remains v0.4.10. No existing installation is updated or restarted.
