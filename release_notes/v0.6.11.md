# Kintsugi v0.6.11

## Optimizer prompt caching

- Keep the initial learned-fact system section stable. New live facts append once to context instead of rewriting the prompt prefix; provider retries retain the same snapshot.
- Preserve trusted fact snapshots through forks and compaction. Rejected, stale or explicitly removed facts are filtered from subsequent requests, including older positional system sections. Ordinary user text containing fact markers is left alone.
- Give optimizer side calls stable, isolated cache affinity by session, purpose and model, with short cache retention. Put the reusable tool catalogue before changing task text.
- Enforce the automatic tool-pick deadline through queue admission, invocation and the final schema-change transaction. Expired work cannot start another model call or apply late tool changes.
- Clarify the cache consequences in Settings and report live fact changes accurately in learning receipts.

Fact removals and intentional tool-schema changes can still invalidate cached context. Offline checks cover ten provider serializers, append-once delivery, retries, compaction, forks and deadlines. Real-model warm-cache savings and paired quality/cost acceptance have not been measured.

## Compatibility and channels

Existing optimizer sessions remain readable. New fact context uses additive durable entries; learning receipts use `activeFactsChanged` in place of `activePrefixChanged`. System compatibility remains 7, the app minimum remains 0, and network/resource policy readers remain 2 and 3. The MCP settings-v2 downgrade restriction from v0.6.9 is unchanged.

This release advances `latest` and, after verification, `stable`. Stable also gains the continuous resource-meter fixes from v0.6.10. Publication does not deploy or restart an installation.
