# Kintsugi v0.4.12

Adds `CH` beside session cost and readable plan-tool timeline summaries, with changes to improve prompt-prefix reuse.

## CH and prompt reuse

- Show a token-weighted prompt hit percentage for Builtin, native Codex and native Claude agents. Reused prompt tokens form the numerator; all prompt tokens, including writes, form the denominator. Output tokens are excluded. Codex's inclusive counters and Claude's disjoint counters are normalised separately.
- Show `N/A` for empty, missing or invalid counters. Providers that normalise unavailable counters to zero can still report zero. Builtin CH covers the current branch, including compaction and model-tool usage; descendant usage is excluded, matching the primary cost before its separate descendant-cost addition.
- Place per-Agent journal instructions after shared project and skill instructions to extend the reusable prefix for new or explicitly refreshed prompts. Existing committed prompts stay unchanged.
- Explicitly use short retention for Builtin generation, retaining persisted provider session affinity across turns and restarts. No warming requests or blanket longer-retention charges are introduced. Compaction, classifiers, image providers and external CLIs retain their separate policies. Actual provider billing savings have not been measured.

## Plan timeline

Plan rows now show text such as `plan · Update checklist · 3 steps` and `plan · Update step 1 · complete — Inspect the implementation`. Single patches show the step and status; bulk operations show a count. Raw arguments and results remain unchanged in expanded details. This changes presentation only; plan ownership, revision checks and execution boundaries stay intact.

## Verification and update scope

Local verification passed **2,697 tests**, with **36 skipped** and **zero failures**, plus frozen install, lint and TypeScript checks. Manual app checks verified CH beside cost using staged accounting data, and readable plan rows with raw details preserved using the offline faux provider. No external inference was used for these fixtures.

Composer layout passed **89/89 checks across six no-inference Chrome scenarios**. Provider sends, busy/long-transcript states and physical/iOS keyboards are not qualified. Tagged publication separately requires full CI and native packaged System/app boot checks.

No dependency, runtime-image pin, compatibility-counter or persisted-format changes. Fork safeguards and attribution remain unchanged. Unrelated local resource-default edits are excluded.

Publication advances `latest` only. `stable` remains v0.4.10. No existing installation is updated or restarted.
