# Kintsugi v0.5.4

## Themes

- Add Catppuccin Mocha, Monokai Pro, Dracula, Gruvbox, Noctis, Lumon, AS/400, SynthWave ’84 and Fallout. Fallout retains PiClaw’s Petrol & Copper palette under the requested name. Existing themes remain available; Latte is not included.
- Add selectable palette swatches in Settings, using the existing saved theme and live updates across open pages.
- Align syntax colours, ANSI terminal colours, selection, focus, button outlines, surface lighting, gradients and shadows with each palette. AS/400 keeps its green phosphor colours; SynthWave uses steady syntax glow, without the animated Full variant.
- Extend the VS Code bridge to carry literal, attribute, tag, constant and link syntax colours. Retain palette provenance and MIT notices.

## Workspace task limits

- Add an editable default task limit in Settings → Workspace resources. It starts at 1,024 tasks and applies to new workspaces; existing allocations are retained.
- Add per-workspace task overrides and current/effective task readings in Properties. Tasks include processes and threads. Changes do not restart the workspace, and reductions below current or unknown usage are refused.
- Keep task limits finite and within the installation’s shared workload budget. Refresh systemd’s implicit task defaults before a cold start so older workspace services do not inherit the unintended 15% cap. Explicit unit limits remain intact.
- Task limits do not increase available RAM or disable the OOM circuit breaker.

- Update the manual LAN verification helper for the WebSocket-only live channel, while retaining the settings SSE check.

## Compatibility and verification

Task controls require System compatibility version 5. The app minimum remains 0, with the new controls gated on running System support. Saved task settings require resource-policy reader 3 and System 5; app-only and installation update/rollback checks reject incompatible targets without discarding settings. Existing version-2 RAM policies remain readable. The network-policy reader remains 2.

Local frozen installs, typecheck, asset/System bundle builds and workflow validation passed. The full local suite passed 2,914 tests with 36 skips and no failures across 405 serial batches.

Chromium acceptance passed for all nine additions, Settings swatches, live second-page updates, persistence, narrow layout, syntax colours and button hover/focus outlines. WebKit acceptance did not complete: its local memory limit triggered an OOM and the workspace safety stop. Composer-layout acceptance was attempted but remained blocked after the local preview/browser were stopped. These checks are not claimed passed; no further local browser acceptance was attempted after recovery. Genuine macOS Safari, certificate trust and physical-device acceptance remain unverified. Tagged publication requires full CI and both native app/System build and packaged boot gates.

## Known limitations

Existing preview-browser storage limitations remain: independent views do not share live IndexedDB transactions/auto-increment, and forced unacknowledged closure of the last WebKit preview can lose recent writes. Opaque previews do not support native service-worker registration or cross-sandbox DOM access.

Publication advances `latest` only. `stable` is unchanged; publication does not update or restart an installation.
