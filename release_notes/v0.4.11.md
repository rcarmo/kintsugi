# Kintsugi v0.4.11

Fixes terminal deadline callbacks reporting `sh …/expire … returned 2` after a command's terminal process was released.

## Fix

`terminal-process.ts` schedules expiry with tmux's delayed `run-shell`. Release removes the process directory and its scripts, but the timer still fires. The deleted `expire` script cannot run its own missing-directory guard, so `sh` exits with code 2.

The scheduled command now checks that the script exists before loading it. It holds the same process-root lock as release while checking and executing expiry, preventing deletion between those operations. A callback for a released process exits successfully. Active deadlines still interrupt commands and kill those that ignore termination; other expiry failures are not suppressed.

Regression tests capture the actual delayed callback's status after releasing both finished and running commands, locally and through the workspace helper. Both cases reproduced exit code 2 before the fix and return 0 afterwards. Local verification passed **2,690 tests**, with **36 skipped** and **zero failures**, plus frozen install, lint and TypeScript checks. Tagged publication separately requires full CI and native packaged System/app boot checks.

This changes newly scheduled callbacks. Timers already queued by an older app keep their old command until they fire or their tmux server stops. Publishing does not restart servers or modify queued callbacks in an existing installation.

No dependency, runtime-image pin, compatibility-counter or persisted-format changes. Fork safeguards and attribution remain unchanged. Unrelated local resource-default edits are excluded.

Publication advances `latest` only. `stable` remains v0.4.10. No existing installation is updated or restarted.
