# Kintsugi v0.4.9

Improves streamed transcripts, Changes concurrency, Files editing and file navigation, and updates the verified Docker runtime.

## Application changes

- Avoid re-walking unchanged transcript subtrees and unnecessary Turbo sibling scans during streaming.
- Keep Changes selections, saved edits and Agent-turn commits consistent when captures overlap or fail. Outdated history selections refresh instead of failing.
- Fix Files editor layout after hiding/showing it, and preserve terminal text/IME input order.
- Add selected-text quoting into the Agent composer and selected-text prefill for a new Agent. Steering starts its own display block within the same execution run.
- Open HTML file links in Browser views, preserving anchors and literal filename characters. Terminal file hyperlinks use the same navigation.
- Distinguish exhausted model-specific Anthropic allowances from account-wide limits, retaining the fork's nullable and validated usage parsing.
- Update coordinated dependencies, including TypeScript 7, Pierre, Gespenst, protobuf and proxy clients. Workspace tools advance to Node 26, tmux 3.8 and the updated pinned CLI tools.

## Verified runtime

Docker **29.9.2**, containerd **2.4.2**, BuildKit **0.34**, runc **1.5.2**, Buildx **0.38.1** and Compose **5.6.1** use the fork's immutable runtime manifest:

`ghcr.io/rcarmo/kintsugi-docker@sha256:5b3106e3e906e30b2d314ce66d53afc1bb816f8bcd91aa578879e13194c5f351`

All eleven runtime Go executables are rebuilt and checked with **Go 1.27.3**; the workspace helper, gateway and CI builders use the same toolchain. Native [runtime verification](https://github.com/rcarmo/kintsugi/actions/runs/40749388943) passed on AMD64 and ARM64, including EROFS cache reuse, offline builds, restart/supervision and delegated-cgroup exec. The new BuildKit cache staging preserves its versioned snapshot identities. Ubuntu's test-only runc patches and licence metadata are retained; runc 1.5.2 contains the exec retry fix previously backported by this fork.

App, System and workspace defaults share that digest. A new regression catches mismatched consumer pins, including the stale app Dockerfile default found during this release.

## Verification and update scope

Linux recordings use Playwright's bundled headless shell instead of forcing the full Chrome binary; setup failures also clean up the browser and capture directory. The existing recording fixture passes. Composer sampling accepts a genuinely empty tmux server after workspace restart, while other errors still fail.

Composer layout passed **89/89 checks across six no-inference Chrome scenarios**. This is partial acceptance: provider sends, busy/long-transcript states and physical/iOS soft keyboards are not qualified. Tagged publication separately gates full CI and real packaged System/app boot on both native architectures.

Browser views can now save `file://` targets and anchors in the existing URL field. An older app may clear an unsupported file target; reopen the preview after upgrading again. No journal migration or compatibility-counter change is introduced. Image rollback preserves data; back up before runtime upgrades or downgrades rather than treating image rollback as a Docker/containerd datastore restore.

Use a paired installation update to update System's Docker daemon as well as the app. Publishing this release does not perform that update. Host terminals, credential grants, exact GitHub token hosts, network/DNS restrictions, explicit Review/plan boundaries, Office/CSV/TSV/Draw.io, source overrides, pins and paired rollback are retained. Unrelated local resource-default edits are excluded.
