# Kintsugi v0.4.18

Makes Builtin plan context append-only across provider APIs, restores Codex WebSocket delta continuation with active plans, and places shared instructions before agent-specific prompt sections.

## Prompt and context caching

Plan snapshots are now committed to model history when they change instead of appended as a transient request suffix. Unchanged plans are not repeated; edits and clearing append a new snapshot. Earlier snapshots remain immutable until normal context compaction removes them. This keeps successive requests append-only and removes the need for Anthropic-only cache-marker rewriting.

The real Codex SDK now sends incremental WebSocket requests with both unchanged and edited plans. Shared instructions are projected before delegation and identity sections before provider serialisation. No provider capability is forced on, cache retention remains short, and no cache-warming requests are added.

Retries keep their pinned snapshot without duplicate journal entries. Reopen, reset, forks and independent child plans retain their ownership boundaries. Plan snapshots are model context, not user submissions: they are hidden from normal transcript turn grouping and do not authorise work. Code-mode slash-command templates still run without provider inference when a plan is active.

## Provider and backend scope

Offline serializer checks cover all ten Pi text-generation APIs: Anthropic Messages, OpenAI Responses, Codex Responses, compatible Chat Completions, Azure OpenAI Responses, Bedrock Converse, Google Generative AI, Google Vertex, Mistral Conversations and Pi Messages. Both short retention and retention-disabled requests are covered, along with native and fallback instruction/tool changes on the relevant APIs.

Native Codex and Claude clients continue to own their provider request construction and caching. Their existing runtime, command and transcript suites pass; Builtin cache settings do not override those clients.

Provider cache acceptance, routing and expiry remain provider-controlled. Genuine model, instruction or tool changes can still invalidate prefixes on APIs that cannot represent changes natively. No live hit-rate or billing improvement is claimed. Append-only plan edits add history until normal compaction; activation can cause a one-time cold prefix.

## Verification and upgrade

Local verification passed **2,740 tests**, with **36 skipped** and **zero failures**, plus frozen install, lint and TypeScript checks. A separate targeted run passed 33 tests. A real SDK transport test against an offline local Codex provider observed one full request followed by two delta requests. Tagged publication also requires full CI and native AMD64/ARM64 packaged System/app boot checks.

This release adds a versioned, conversation-scoped plan-request document and append-only plan-context entries. Existing journal records and saved instructions are not rewritten. No dependency, runtime-image pin or compatibility-counter changes. Fork attribution, cancellation, network and credential safeguards are retained.

Publication advances `latest` only; `stable` remains v0.4.10. No installation or workspace is updated or restarted by publication. The existing-workspace task-cap repair instructions from [v0.4.16](v0.4.16.md#upgrading-workspaces) still apply.
