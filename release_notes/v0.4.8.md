# Kintsugi v0.4.8

Updates automation guidance and the opt-in review workflow, and corrects the highlighting benchmark's streaming sample count.

## Changes

- Document workspace `warnings`, queued follow-ups, submission identities, steering, cancellation and resuming input left behind by a failed turn.
- Run `/review` through one fresh reviewer with structured findings, reproduction evidence, stored-state and upgrade-risk checks. The workflow never automatically fixes files, stages changes or commits. Further rounds require explicit approval. The reviewer receives `read` and `bash`; Bash is not an operating-system-enforced read-only boundary.
- Count decoded content prefixes in the write benchmark, matching `renderToolCard`, and add a regression check. Update the benchmark guide for the current Highlights and Pierre renderers.

## Verification and limits

86 targeted tests passed in isolated file runs; lint and TypeScript checks passed. A combined route/runtime test invocation encountered fixture-lock teardown errors; all affected tests passed when run in separate processes. The tagged release runs the full suite and native image gates before publication.

Three Bun 1.4.4 Linux ARM64 benchmark runs passed 50/52, 49/52 and 49/52 cases. Every expected update completed, and every streaming replay passed its budgets. Bash/heredoc cases still exceeded existing timing targets; the slowest cold render was 88.4 ms and one shared highlight took 22.9 ms. No budgets were loosened. These measurements do not establish a Bun-only speedup or browser responsiveness. See the [benchmark results](../packages/syntax/bench/RESULTS.md).

No runtime protocol, compatibility counter, application environment variable or installation data format changes. The review script runs only when explicitly requested. Existing credential grants, network boundaries, custom sources, image pins and paired rollback are unchanged. The v0.4.7 runtime pin is retained. Unrelated local resource-default changes are excluded.

Publication advances `latest` only. `stable` stays at v0.4.1. No existing installation is updated or restarted.
