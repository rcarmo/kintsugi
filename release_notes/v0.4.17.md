# Kintsugi v0.4.17

Fixes individual-tool cancellation, terminal exit-status races and workspace socket initialization failures, and raises eligible new-workspace RAM defaults to 4 GiB.

## Individual-tool Stop

Per-tool cancellation no longer queues behind new-turn admission or waits for Docker, image or workspace readiness probes. It checks the selected conversation's live slot and task, then requests native durable cancellation of that call and its owned work.

Sibling tools, queued input and the Agent turn are retained. User cancellation notes reach the tool result. A running one-shot tool can be cancelled without making its conversation editable; ordinary read-only history and foreign-conversation guards stay intact. TERM-cooperative and TERM-ignoring shell commands are covered, including escalation and process termination.

Cancellation cannot roll back external effects, guarantee stopping detached remote work, or confirm physical cleanup while the workspace helper is unreachable. No automatic container restart or unsafe RPC replay is introduced.

## Terminal and socket reliability

Processes stopped before starting, or whose deadline already passed, now publish the `none` exit status with a temporary file and atomic rename. Readers no longer see a partially written status. Async workspace WebSocket initialization failures are logged and close that socket with code 1011 instead of escaping into the management app.

## Workspace RAM default

New workspace defaults are now up to **4 GiB RAM / 4096 MiB**, reduced on smaller installations. CPU, additional-swap and PID defaults are unchanged. Existing explicit limits are preserved; an existing 2 GiB workspace is not automatically raised.

The default is owned by System. Use a paired installation update to obtain it. App-only updates supply the cancellation and socket fixes but do not change the installed System policy. Existing workspace RAM can be adjusted explicitly in Workspace Properties.

## Verification and publication

Local verification passed **2,728 tests**, with **36 skipped** and **zero failures**, plus frozen install, lint and TypeScript checks. Regressions cover stalled readiness/admission, cancellation notes, sibling and foreign-root isolation, read-only one-shots, real long-running shell termination, atomic exit-status publication and async socket failure handling.

A manual running-app fixture used the actual Stop dialog and route: HTTP 200 returned in 184 ms, the selected TERM-ignoring command terminated, its sibling survived and completed normally, and the Agent continued. The fixture used an offline faux provider and isolated acceptance data; no real user operation was cancelled. No UI assertions were added to the test suite. Tagged publication separately requires full CI and native packaged System/app boot checks.

No dependency, runtime-image pin, compatibility-counter or persisted-format changes. Fork safeguards and attribution remain unchanged. The systemd task-cap fix and existing-workspace repair instructions from [v0.4.16](v0.4.16.md#upgrading-workspaces) still apply; updating the app does not replace existing workspace images.

Publication advances `latest` only. `stable` remains v0.4.10. No existing installation is updated or restarted by publication.
