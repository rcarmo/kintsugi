# Kintsugi v0.6.9

## MCP settings and sharing

- Save endpoint edits without re-entering a saved bearer token. Credentials remain privately bound to the old endpoint until replaced or explicitly approved for reuse. Changed connections save disabled when approval or OAuth sign-in is needed.
- Share an HTTP server across selected workspaces or all workspaces, including future ones. Filter the workspace picker and choose all or selected Agents within each workspace.
- Enforce current grants for discovery, code-mode schemas, calls and retained recall. Revoked access also blocks tool definitions captured by an already-running code-mode script.
- Keep stdio servers bound to one execution workspace. Reject duplicate server names across overlapping workspace grants and track shared connection status independently per workspace.
- Reuse an approved OAuth login when sharing the same endpoint. Endpoint changes require a new sign-in; disabled connections must be enabled first.
- Preserve schema-less MCP structured content as text for nested code-mode calls. Only servers declaring an output schema supply structured return values; explicit MCP errors still reject.

## Compatibility

Existing version-1 MCP settings load without broadening grants. Saving a connection writes version 2. Apps through v0.6.8 cannot read that format; keep a pre-upgrade app-data backup if a downgrade is needed. Image rollback does not restore settings files.

These changes are app-owned. System compatibility remains 7, the app minimum remains 0, and network/resource policy readers remain 2 and 3. Custom release sources, version pins and workspace images are unchanged.

## Verification

Local verification covered URL save/reload, private credential persistence and approval, OAuth binding and login reuse, per-Agent schema isolation, runtime revocation, recall isolation, future-workspace grants and stdio restrictions. Manual review used managed Chromium at desktop and mobile widths, including an OAuth sign-in shared across two workspaces without another authorisation. Physical iPad/WebKit acceptance has not been verified.

Publication advances the version tag and `latest`, leaves `stable` unchanged, and does not deploy or restart an installation.
