# Kintsugi v0.6.2

## Optimizer timeline

- Show new optimizer activity as expandable tool-style rows in the Agent timeline, reusing the existing tool-call renderer for inputs and outputs. Normal states use a blue indicator; failures keep the usual error indicator.
- Include background learning, model calls, nudges, task tool selection, hiding/restoring tools and classifier retraining. Rows show queued/running/completed states, elapsed time and available model usage/cost data. Routine empty or throttled checks stay hidden.
- Record transitions transactionally and group updates into one row per operation. Inputs and outputs are redacted and bounded before display. Operations belong to their originating Agent, including subagents, rather than the maintenance conversation.
- Keep these records out of model context and tool-result evidence. Timeline visibility adds no inference calls and leaves existing learning budgets and throttles unchanged. Earlier optimizer history is not backfilled.

## Compatibility and verification

App-only; compatibility counters are unchanged. Older apps ignore the new display-only entries. The optimizer remains experimental and off by default. Restore hidden tools before downgrading to an app without Restore controls.

Local verification passed 1,559 tests across 125 files with no failures, plus lint, TypeScript and the production client asset build. Backend checks cover receipt storage, originating-Agent attribution, redaction, replay deduplication, model-context exclusion and unchanged inference counts.

Manual review used the real app with clearly labelled offline examples at desktop and mobile widths. The existing six-scenario composer acceptance script passed in partial/no-inference mode. Full inference-driven composer acceptance and real-provider cost/quality measurements remain outstanding.
