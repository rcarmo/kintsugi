# Kintsugi v0.6.10

## Continuous resource meters

- Collect System and all unparked workspace counters for the app's lifetime, independently of open browsers or the selected workspace. Opening a workspace shows its already-collected history; collection never starts parked containers.
- Sample workspaces in bounded batches without excluding installations with more than 32 active workspaces. Preserve separate histories and CPU/I/O baselines between batches.
- Plot observations at their uneven timestamps, retaining missing-data gaps. Keep wall-clock observation time separate from the monotonic clock used to calculate rates.
- Ignore duplicate cached samples, insert delayed observations before existing failure markers, and rebase rates safely when the counter process restarts.
- Rename the visible Memory label to RAM.

History remains bounded and in memory for the app's lifetime; it does not survive an app restart.

## Compatibility and verification

New counters include an optional wall-clock observation time. Older System meter responses remain supported using arrival times. System compatibility remains 7, the app minimum remains 0, and network/resource policy readers remain 2 and 3. Existing sources, pins and MCP settings compatibility are unchanged.

Backend verification covers viewer-independent sampling, cancellation and stale-result fencing, a 70-workspace fixture, irregular and delayed observations, legacy counters and clock restarts. Managed Chromium review confirmed populated workspace and System charts on the first view after a period with no subscriptions, at desktop and mobile widths. Physical iPad/WebKit acceptance has not been verified.

Publication advances the version tag and `latest`, leaves `stable` unchanged, and does not deploy or restart an installation.
